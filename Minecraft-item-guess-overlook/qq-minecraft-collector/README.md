# 幽幽子 Minecraft 物品采集器

双击 `启动采集面板.cmd` 打开控制面板。

1. 启动 QQ 后台，打开扫码登录，用手机 QQ 确认登录。
2. 检查连接。目标默认自动查找“幽幽子”；如果找不到，填入机器人的 QQ 号。
3. 先读取已有回复，再试采集 3 项。确认机器人回复正常后采集剩余物品。
4. 数据自动保存在 `data/items.json` 和 `data/items.csv`。可以随时暂停并续跑。

## 数据规则

- 名称及九类标签按机器人表格原文保存，同一列使用独立标签。
- 只用表格中已经给出的标签，不根据正文新增类别。“无”保留为标签。
- 堆叠数量和初始版本中的箭头在送入文字识别前遮挡，不保存箭头或比较颜色。
- 保留原始图片、逐字段识别置信度、目标机器人的原始回复，方便复核。
- 物品队列来自中文 Minecraft 维基物品列表，链接相同的条目合并；当前队列不代表机器人一定支持全部物品。
- 机器人数据和当前维基可能不同；导出数据明确标注来源为幽幽子机器人。

## 名称对应与复查

不靠特定物品名单、后缀或相似字词合并名称。每次查询前保留当前表格的名称列；查询后若只追加一个新物品行，就确认发送名称与该行名称的对应关系。已确认关系保存在 `data/name-map.json`，并在数据中保留查询名称、确认依据和维基来源。

如果机器人明确表示不认识页面标题，会尝试维基物品列表中确实指向同一页面的其他名称；仍不被接受的条目标为未收录，不凭空补数据。

“已经猜过”只在名称已确认，或当前独立新局只有一个物品行时用于确认对应关系。表里有多个候选物品时，加入复查队列，使用 `/结束猜mc` 结束当前游戏、再用 `/猜mc物品` 开新局验证。无法确认结束或开局时暂停；发送结果不明确时不自动重发。

多个查询名称可以对应一个机器人名称；维基页面的身份与机器人名称分别保存，不按机器人名称把不同的维基页面合并。若同一个返回名称出现不同标签，两份证据保存在 `data/conflicts.json`，该条数据标记为需要复核。

识别每张表的名称列以定位目标，只识别目标行的九类标签。旧物品行的其他字段不会重复全部读取。

表格满 12 行后，机器人会移除最早一行。只有其余行保持原来顺序、且末行名称是唯一新增时，才用滚动变化确认查询名称。维基重定向旧名和底部物品导航中的额外候选，连同出处保存在 `data/wiki-extra-aliases.json`。

行边界从名称单元格的空白边缘定位，长名称不会把一行切碎。低置信度文字会增加周围留白后重新识别，仍使用原来的 92% 阈值；复核前后的文字与置信度一起保留。箭头在两次识别前均已遮挡。

维基列表中的版本注记链接不作为物品加入队列。收尾核对会生成 `data/coverage.json` 和 `data/采集结果说明.md`，逐项列出已采集、机器人未收录和仍需处理的状态。

## 暂停及异常

查询间隔为收到回复后等待 5 秒，逐个等待回复。目标为 197 个已核对的独立机器人物品；达到目标后自动停止，不要求把所有别名重复问完。连续失败三次、机器人要求稍后再试时暂停。名称不明确的“已猜过”进入复查队列，不算采集失败。发送超时不会自动重发，以免重复发送。

`finish_target.py` 会先补读已有表格中遗漏或待复核的行，再核实同一维基页面下未查询过的具体名称。这些名称需要各自的机器人回复证据；同一页面已返回一个物品，不会使其他候选物品被直接跳过。多个维基名称可以对应同一个机器人物品，同一维基页面也可以对应多个机器人物品。

进度和 JSON 数据先写入独立临时文件，再替换旧文件；Windows 暂时占用旧文件时会短暂重试。持续拒绝访问时保留旧数据及新的临时副本，并停止任务供检查。恢复时先读取机器人已有回复，确认上一条发送结果后续跑。

查询指令为 `/我猜mc是物品名称`，开局指令为 `/猜mc物品`。明确收到游戏结束或尚未开局的回复时，程序会开启新一轮，并确认开局回复后继续。无法确认开局、发送结果不明确或机器人要求稍后再试时暂停。

界面关闭后可以继续后台采集。Windows 关机或账号退出后，需要重新启动并登录。工具没有创建开机启动任务。

## 组件及访问

使用 NapCat v4.18.38 的独立 Node 运行版和 RapidOCR 3.10.0。后台只监听 `127.0.0.1`，使用随机访问令牌。只保存选定机器人的消息，不保存其他联系人的聊天。

组件来自 [NapCat 官方发布](https://github.com/NapNeko/NapCatQQ/releases/tag/v4.18.38)，下载文件已经与发布页的 SHA256 校验。说明见 [NapCat 接口文档](https://doc.napneko.icu/develop/api) 和 [RapidOCR 文档](https://rapidai.github.io/RapidOCRDocs/main/en/install_usage/rapidocr/install/)。

源码：`collector.py`（后台通信和采集）、`vision.py`（表格识别）、`names.py`（名称对应关系）、`control_panel.py`（控制面板）。依赖只安装在本工具的 `runtime/venv` 中。`config.json` 含本地访问令牌，不应上传到公共仓库。
